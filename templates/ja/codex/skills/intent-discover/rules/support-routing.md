# 支援選択

`intent-discover` が mode を選ぶ前に、今回必要な支援を判断するための規則。支援先は職種別の固定表から選ばず、現在利用できる利用者向けの skill または工程だけを案内する。この規則自身や内部の rule は支援先として表示しない。

## 入力

目的、成果物、指定資料、次の判断を、否定や前後関係を含む依頼全体の意味で組み合わせる。職種、経験、単語、ファイル名だけでは支援を固定しない。

資料は、最初の重要な判断に必要な範囲だけを扱う。全資料の読了を質問開始の条件にしない。読めた内容と読めない制約を分け、読めない内容を推測しない。

## 結果

評価結果は次の四つから一つだけ返す。

1. `AvailableSupport`: 現在の配置で実在を確認した、利用者向けの skill または工程だけを `AvailableSupport` とする。対象、選定理由、利用者が次に行う操作、終了後の復帰先を示す。
2. `SupportCandidate`: 必要な個別分野は判断できるが、対応工程の実在を確認できない場合に返す。`SupportCandidate` は利用可能と表現しない。必要な支援候補、足りない工程、今進められる既存 flow を示す。
3. `ClarificationQuestion`: 候補によって成果が変わり、利用可能な情報だけでは選べない場合に限り、`ClarificationQuestion` で一問だけを出す。その回答で変わる結果も示す。入力が空、または必要な資料を読めず支援を選べない場合は、推測せず足りない情報を一度に少数だけ示す。
4. `ExistingFlow`: 新しい支援案内が不要なら、`ExistingFlow` から既存の mode 選定または既存 flow をそのまま続ける。支援を選べる場合は分類のための追加質問を出さない。

利用可能性を確認できない専門支援や未実装の後続工程を `AvailableSupport` にしない。個別分野の詳しい規則はここで読まず、選ばれた利用者向け支援に委ねる。発注文脈のない通常案件には、発注質問や RFP 形式を追加しない。

## 資料取り込みの案内

詳しい資料取り込みが必要な場合だけ、その用途、利用する既存工程、利用者の次の操作、終了後の復帰先を案内する。既存工程は `intent-from-spec` であり、支援選択へ戻るための案内に限る。資料取り込みを自動実行しない。

資料がない、または詳しい取り込みが支援選択と重要な質問に不要なら、資料取り込み工程の詳しい指示を読まない。ファイル名だけを根拠に資料を読んだり支援を選んだりしない。

## 同じ資料の再評価

- 同じ資料とみなせるのは、現在読める会話または既存成果物から、同じ指定元と同じ版だと確認できる場合に限る。その場合は既存の選定結果、質問、変更候補を再利用し、同じ項目を追加しない。
- 版変更または内容変更の申告があれば別資料として変更部分を再評価する。全資料を読み直すことは前提にしない。
- 同一性が不明なら、処理済みとも別資料とも推測しない。版または変更有無によって支援結果や次の質問が変わる場合だけ、一問で確認する。変わらない場合は確認せず既存 flow を続ける。
- 重複防止は、現在読める会話と出所をたどれる既存成果物の範囲で行う。新しい fingerprint 台帳や永続的な routing 状態は作らない。

## 禁止事項

利用者属性データベース、固定的な職種分類、機械スコア、永続的な質問台帳を作らない。全資料の提出を前提にせず、内部 rule を利用可能な支援として示さず、資料取り込みや個別分野の処理を代行しない。
